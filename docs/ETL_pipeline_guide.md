# Employee Analytics - ETL Pipeline Documentation

This document explains the architecture of the ETL pipeline, the purpose of each script, and the exact sequence of commands required to build and populate the Data Warehouse.

##  File Explanations

### 1. Database Setup (SQL)
*   **`01_oltp_ddl.sql`**
    *   **What it does:** Creates the operational database (`employee_oltp`). This is a highly normalized (3NF) schema designed for the Streamlit app's daily transactions (adding employees, submitting reviews, etc.).
*   **`02_olap_ddl.sql`**
    *   **What it does:** Creates the Data Warehouse (`employee_dw`). This is a Star Schema containing Fact tables (Performance, Allocations) and Dimension tables (Employee, Date, Project, Department). It also includes optimized indexes for fast querying.

### 2. ETL Logic (SQL)
*   **`03_etl_procedure.sql`**
    *   **What it does:** Creates the Stored Procedures in the Data Warehouse. These procedures contain the "brains" of the ETL. They extract data from the OLTP database, transform it (handling **SCD Type 2** for employee history, mapping surrogate keys, and formatting dates), and load it into the Star Schema.
*   **`04_run_etl.sql`**
    *   **What it does:** The SQL execution script. It contains the `CALL` statements to execute the Stored Procedures created in `03_etl_procedure.sql`. It enforces the correct execution order: loading Dimensions first, then Fact tables. *(Note: We use `run_etl.py` to execute this instead of MySQL Workbench to prevent 30-second timeout errors).*

### 3. Data Loading & Orchestration (Python)
*   **`load_data.py`**
    *   **What it does:** The bulk loader. It reads the synthetic CSVs generated by the Faker script (`data/processed/`), cleans the data (removes duplicates, renames mismatched columns), and inserts 100,000+ rows into the OLTP database. It also performs the initial bulk load of the 160,000+ historical SCD Type 2 records into `Dim_Employee`.
*   **`run_etl.py`**
    *   **What it does:** The Python orchestrator. It connects to MySQL and executes the Stored Procedures. Because it bypasses the MySQL Workbench GUI, it can process heavy 490,000+ row fact table joins without timing out.

## Step-by-Step Execution Sequence

Follow this exact order to build the project from scratch.

### Phase 1: Database Creation
Open **MySQL Workbench** and run these scripts in order:
1. Run `01_oltp_ddl.sql` (Creates the OLTP schema).
2. Run `02_olap_ddl.sql` (Creates the Data Warehouse Star Schema).
3. Run `03_etl_procedure.sql` (Creates the ETL Stored Procedures).

### Phase 2: Initial Data Load (OLTP)
Open your terminal in VS Code (ensure `.venv` is activated) and run:
1. `python load_data.py`
    *   *Expected Output:* Loads ~100k employees, ~141k assignments, and ~491k reviews into the OLTP database. It will also load 160,136 historical SCD2 records directly into `Dim_Employee`.

### Phase 3: Execute the ETL (Populate DW)
In the terminal, run the Python orchestrator:
1. `python run_etl.py`
    *   *Expected Output:* Connects to MySQL and executes the procedures from `04_run_etl.sql`. It will take 60–90 seconds to load the Fact tables. You will see success messages with timestamps.

*(Alternative: If you prefer to run it in MySQL Workbench, you can open and run `04_run_etl.sql`, but be aware of the 30-second timeout limit).*

### Phase 4: Verify the Data Warehouse
Run this query in MySQL Workbench to confirm the Star Schema is fully populated:
```sql
USE employee_dw;
SELECT COUNT(*) FROM Dim_Employee;                 -- Expected: ~160,136
SELECT COUNT(*) FROM Dim_Department;               -- Expected: 3
SELECT COUNT(*) FROM Fact_PerformanceReviews;      -- Expected: ~491,000
SELECT COUNT(*) FROM Fact_ProjectAllocations;      -- Expected: ~141,000
